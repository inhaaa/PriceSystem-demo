# PriceSystem 공고 작업대 적용

사용자가 승인한 `공고 작업대` 시안을 실제 Streamlit 화면에 적용한다. 이후 추가한 요구는 관심공고 등록 → 개찰일별 조회 → 계산이라는 짧은 업무 흐름과 업무 홈의 날짜별 일정이다. 이 승인은 디자인 적용 요청에 포함되어 있으므로 별도 승인 단계를 만들지 않는다.

## 화면 원칙

- 기존 왼쪽 메뉴의 이름·순서·색·선택 상태와 계정 기능은 유지한다.
- 본문은 흰 작업면, 옅은 회색 배경, 중립색 본문, 딥그린 주요 버튼을 사용한다. 큰 슬로건·장식 그래픽·큰 바로가기 카드를 없앤다.
- 제목은 24px 안팎, 숫자는 자릿수 정렬, 줄과 선택 상태로 정보 위계를 만든다. 로딩·빈 상태·저장 완료·오류를 실제 데이터에 맞춰 표시한다.
- 조회/계산 화면은 공고 목록과 작은 실행 패널을 나란히 두며 모바일에서는 순서대로 쌓는다. 상세 정보 탐색은 주 흐름에 넣지 않는다.
- 보조 메뉴도 동일한 제목·도구·표·폼·버튼 톤을 적용한다. 기존 기능을 제거하거나 실제 분석 기능을 새로 만들지 않는다.

## 업무 흐름 및 인터페이스

1. 업무 홈: `store.notices()`의 `deadline`으로 그룹화한 등록 공고 일정을 표시한다. 저장된 추천 건수는 현재 세션 `demo_recommendations`를 기준으로 계산한다. 관심 표시 구분 필드가 없으므로 홈 집계는 `등록 공고 기준`이라고 명시한다.
2. 날짜 이동: `workspace.open_daily_notices(opening)`은 유효한 ISO 날짜 또는 `date`를 받아 날짜별 공고 화면의 `daily_notices_date`, `daily_notices_query`를 설정하고 해당 탭을 연다. `workspace.open_daily_calculation(opening)`은 기존 `daily_requested_date` 계약으로 계산 화면을 연다.
3. 등록: 기존 등록/중복 방지/복원 동작을 유지하고 관심공고 탭을 첫 순서로 둔다. 등록 직후 등록한 날짜의 공고 조회로 연결한다.
4. 날짜별 조회: 공고번호·공고명·기초금액·개찰일·계산 이력을 우선 노출한다. 조회 결과 옆에 선택 건수와 계산 이동을 배치한다. 삭제 확인과 보관 동작은 그대로 유지한다.
5. 계산: 날짜와 간단한 조건으로 조회 → 공고 선택/확인 → 샘플 선택/계산/저장을 실행한다. 상세기관·PDF는 계산 작업대에 노출하지 않는다. 고정 샘플이라는 경계를 분명히 유지한다.

## 데이터·안전·검증

DB 스키마, 외부 연동, 환경 변수와 설정 파일은 변경하지 않는다. 현재 메모리 데모의 데이터 처리 계약을 유지하며 운영 배포는 수행하지 않는다. 입력 오류·삭제 확인·CSV 보호·테마 전달·수평 탭·모바일 메뉴를 보존한다.

일정 그룹·빈 데이터·날짜 이동·등록 후 이동·계산 가드/저장에 대해 테스트를 먼저 추가한다. 전체 unittest와 실제 브라우저에서 로그인→홈→등록→날짜별 조회→계산/저장, 주요 보조 메뉴, 1440/1024/768/390/320px 및 다크 모드를 확인한다.
