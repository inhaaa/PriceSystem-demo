# 투찰 검토함 설계

사용자가 앞서 제안한 투찰 검토함 구성의 구현을 요청했다. 기존 디자인에 맞춘 체크리스트·상태 변경을 이번 범위로 확정하고 같은 작업 공간에 추가한다.

## 화면과 동작

- 새 `업무 관리` 메뉴 그룹에 `투찰 검토함`(`bid_review`)을 추가한다.
- 상단은 전체 등록 공고의 검토대기·준비중·검토완료·보류 건수, 아래는 검색·분류·상태 필터와 공고 목록/검토 패널이다.
- 공고별 참가 자격·조건 확인, 필수 서류 준비, 투찰금액 확인, 제출 일정 확인의 네 체크와 검토 메모를 명시적으로 저장한다.
- 검토완료는 네 체크가 모두 참이어야 한다. 실패한 저장은 기존 값을 보존한다. 나머지 상태는 체크 개수와 독립적으로 변경할 수 있다.
- 공고 전환·업무 탭 전환 후 저장 내용이 유지된다. 공고별로 다른 위젯 키를 사용하며 다른 공고로 내용이 섞이지 않는다.
- 빈 목록과 검색 결과 없음 상태를 제공한다. 검토 상태는 실제 투찰의 제출완료 상태를 변경하지 않는다.

## 데이터 계약

SQLite 스키마와 설정을 변경하지 않는다. `st.session_state['demo_reviews']`의 공고 ID별 사전을 사용한다.

```python
REVIEW_STATUSES = ('검토대기', '준비중', '검토완료', '보류')
REVIEW_CHECKS = (
    ('eligibility', '참가 자격·조건 확인'),
    ('documents', '필수 서류 준비'),
    ('amount', '투찰금액 확인'),
    ('schedule', '제출 일정 확인'),
)
# 각 공고의 기본값
{'status': '검토대기', 'checks': {key: False for key, _ in REVIEW_CHECKS}, 'note': ''}
# demo/services.py의 인터페이스
get_review(reviews, notice_id)
save_review(reviews, notice_id, *, status, checks, note='')
```

조회 결과는 원본과 분리된 복사본이다. 저장 전 ID·상태·체크 키/불리언·메모(최대 1000자)를 검증하고 유효할 때 한 번에 반영한다. 메모는 일반 텍스트, HTML에 넣는 공고 필드는 escape한다.

삭제 공고의 기존 세션 메타데이터 보관·복원 흐름에 `demo_reviews`를 포함한다. 샘플 초기화·로그아웃·새 세션에서 검토 내용을 초기화한다.

## 디자인과 검증

기존 딥그린 사이드바, 흰 작업면, 테마 토큰과 native Streamlit 폼·표를 재사용한다. 좁은 화면에서는 목록과 검토 패널을 세로 배치한다.

모델·화면 테스트를 먼저 작성해 누락된 기능으로 실패함을 확인한 후 구현한다. 체크/상태/메모 저장, 완료 조건, 공고 및 탭 이동, 필터, 빈 상태, 세션 격리·초기화, 보관·복원을 검증한다. 전체 unittest 및 로컬 브라우저에서 데스크톱·좁은 화면을 확인한다. 운영 배포와 git push는 범위 밖이다.
